# 0.2.0rc4 本地实时答辩候选版本

本轮在 rc3 的独立 CPU 环境和离线模型交付基础上，补齐独立 GPU 实时链路：浏览器逐帧发送 JPEG，经 WebSocket 返回抠像结果，并在页面展示实际帧率、往返延迟和服务端处理时间。rc3 备份保留在 `backups/before-v0.2.0rc4-50142e3/`。

## 交付变化

- 新增独立 `.venv-gpu` 启动路径和 `Start-Realtime.cmd`，默认使用 CUDA、离线 RVM MobileNetV3 和本机回环地址；不会在启动时下载模型或安装依赖。
- 新增 FastAPI/WebSocket 实时服务与单页前端，支持浏览器摄像头和本地视频两种来源、320/640/960/1280 宽度、green/blur/alpha/foreground/side_by_side 模式。
- 采用单会话、单帧在途和消息大小上限；服务端校验来源、JPEG 头、像素边界、模型包及源码身份，断开或重置时清理循环状态和 CUDA 缓存。
- 新增实时服务协议、启动器、前端控制器和 GPU 验收测试，并冻结 Windows/Python 3.10/CUDA 12.1 运行依赖清单。

## 使用与验证

GPU 环境要求、浏览器操作、端口与 HTTPS/WSS 边界见[实时预览说明](REALTIME.md)。当前 GTX 1660 Ti 6GB 在合成输入上实测：320 宽约 33.7 FPS，640 宽约 17.8 FPS，960 宽约 9.45 FPS；答辩建议默认 640 宽，追求流畅度时使用 320 宽。首帧模型加载和 CUDA 预热约 2.86–4.40 秒，应在现场说明中单独展示。

CPU 独立环境全量工程回归为 **666 passed、1 skipped**，覆盖率 **90.35%**；实时针对性测试为 **140 passed**。GPU 复验和报告路径见[验证记录](VALIDATION_v0.2.0rc4.md)。GPU 基准使用合成移动图形，不能替代真人发丝、弱光、遮挡、跨浏览器摄像头和远程网络验收。

## 现场边界

实时服务默认只监听 `127.0.0.1`，只允许一个活动会话；第二个连接会收到 busy 错误。浏览器摄像头授权、目标机器驱动、真人素材、长时间温度/显存稳定性和 HTTPS/WSS 仍需在答辩机现场完成。项目包不包含 Python、CUDA 驱动和运行环境；离线 RVM 包需按证据清单另行准备。

本版本是本地答辩候选包，未创建远端 Release；申报中的社区指标和发布指标以平台真实记录为准。
